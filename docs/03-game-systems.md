# 03 게임 시스템 설계

> **기획 값·규칙의 SSOT는 [GDD.md](../GDD.md)다.** 이 문서는 GDD의 게임 시스템을 **구현(엔지니어링) 관점**으로 재구성한 해설이며, 수치·규칙이 이 문서와 다르게 읽히면 GDD가 이긴다.

> **현재 상태**
> M0 구현이 `feat/m0-skeleton`에서 진행 중이다. 아래의 모듈명(`CookingModel.ts` 등)은 M0 스펙의 **파일 계획**이며, M1+ 시스템의 구현 파일은 각 마일스톤 스펙에서 확정한다. 아키텍처 경계(순수 모델/뷰 분리)는 [02-architecture.md](02-architecture.md) 참조.

## 2. 계란 블롭 — M0 (GDD §6.1)

계란 1개 = 중심 기준 **방사형 정점 40~64개 폴리곤 블롭**. 시간에 따라 정점이 바깥으로 퍼진다: 정점별 **시드 노이즈**(구현은 자체 1D 밸류 노이즈 — [adr/0007](adr/0007-value-noise-over-perlin.md)) + **이웃 정점 스무딩** → 자연스러운 비정형 원.

구현 관점 요점:

- **정점 배열이 곧 데이터 계약**이다. M1 원형도 채점 Q=4πA/P²가 이 배열을 무수정으로 소비하므로, `getPolygon()`은 각도 순서를 보존해야 한다(계약 테스트로 고정 — [04-testing.md](04-testing.md)).
- 퍼짐 갱신은 **in-place**(per-frame 할당 0 — 성능 예산, [01-overview.md](01-overview.md)).
- **깨는 위치가 형태에 영향**: 팬 중앙에서 멀수록, 다른 계란과 가까울수록 초기 형태 불리. 겹치면 흰자 융합(융합 덩어리는 개별 채점 불가, 평균 폭락) — 융합 처리 자체는 M1.
- **노른자** = 중심 근처 원. M0는 **렌더만** 하고, 파손 로직(과한 뒤집기 충격, 강도 이벤트)은 M1+. 파손 시 해당 계란 **-15.000점** 고정 감점(§5 감점 표 참조).

## 3. 익힘 FSM — M0 (GDD §6.2)

`doneness`(유효 조리 시간, 초) = Σ `dtSec × heatCoeff`. 상태는 별도 저장 없이 doneness에서 **파생**된다 — 전이 로직이 임계 비교 5줄로 줄고 경계값 테스트가 단순해진다. **단방향·역행 없음. 비교는 전부 `≥`(닫힌 하한) 통일.** `update()`는 **이번 틱에 발생한 전이 목록을 반환**해 큰 dt로 다중 임계를 통과해도 중간 상태가 유실되지 않는다.

M0 스펙 §6의 전이표(초기 시안 수치는 **스펙에만** 둔다 — 값은 `balance.ts`에서만 조정):

| 현재 상태 | 다음 상태 | 전이 조건 (`balance.ts` 상수) | placeholder 표현 |
|---|---|---|---|
| RAW | SET | `doneness ≥ COOK.SET_AT` | 반투명 흰자 → 불투명 시작 |
| SET | PERFECT_WINDOW | `doneness ≥ COOK.PERFECT_START` | 흰자 완전 불투명 |
| PERFECT_WINDOW | OVERDONE | `doneness ≥ COOK.PERFECT_END` | 가장자리 갈변 |
| OVERDONE | BURNT | `doneness ≥ COOK.BURNT_AT` | 짙은 갈색 → 검정 |
| BURNT | SMOKE | `doneness ≥ COOK.SMOKE_AT` | 검정 + HUD "SMOKE!" 경고 |
| SMOKE | **(M0 종단)** | `smokeElapsed ≥ COOK.SPRINKLER_DELAY` → `cook:smokeCritical` 발행 + HUD 점멸 | 스프링클러 실패 연출·스테이지 종료는 **M3 소관** |

**열원 계수** — `heatCoeff`는 주입식이다. GDD §6.2의 5종 계수는 `balance.ts`에 선기입하되, M0 씬은 gas만 사용한다. `heatCoeff = 0`이면 doneness 정지 — M5 "불 끄기" 이벤트가 FSM 무수정으로 해결되는 근거.

| 열원 | 속도 계수 | 특성 |
|---|:---:|---|
| 가스 스토브 | 1.0 | 기본. 야간 스테이지 "불 끄기" 이벤트 대상 |
| 인덕션 | 0.8 | 균일하고 느긋함 |
| 화롯불 | 1.3 | 가장자리부터 탐 |
| 캠프파이어 | 1.5 ± 0.3 랜덤 요동 | 불규칙 — 게이지 주시 필요 |
| 용암 분출구 | 2.5 | PERFECT_WINDOW 극단적으로 짧음 |

> [!NOTE]
> SMOKE 진입 후 3초 방치 → 스프링클러 발동 → 스테이지 즉시 실패(GDD §6.2). 이 3초는 **실시간(dt 누적, 열원 계수와 무관)** 으로 잰다 — [adr/0005](adr/0005-smoke-timer-realtime.md) (원 항목 M0-2).

## 4. 뒤집기 판정 — M1 (GDD §6.3)

홀드하면 0→1→0 **왕복형** 게이지(낚시 캐스팅식)가 돌고, 릴리즈 시점 값 = `p`. 판정 = **(릴리즈 순간의 익힘 상태) × (p가 스테이지별 스윗스팟 범위 안인지)** 의 2차원 표다. 구현 관점에서는 `(익힘 상태, p, 스윗스팟 범위) → 판정 enum`의 **순수 함수**로 만들어 표의 전 분기를 유닛테스트한다.

| 상태 | 결과 |
|---|---|
| **RAW에서 뒤집기** | 계란이 발사체가 되어 **앞 손님 피격** → 손님이 가게 물건(아이템) 1개 훔쳐 도주. 훔친 게 대응 아이템(예: 펜싱칼)이면 해당 이벤트 **방어 불가 상태** 돌입 |
| SET~PERFECT + p 스윗스팟 | 클린 착지(변형 최소) — 만점 루트 |
| SET~PERFECT + p 부족 | 반접힘 — 폴리곤 대변형, 점수 폭락 |
| SET~PERFECT + p 과다 | 팬 밖 이탈 — 계란 로스트(재고에서 이미 소모됨, 다시 깨야 함) |
| **OVERDONE/BURNT에서 뒤집기** | 까만 뒷면 공개 → 현재 손님이 분노, **재고에서 계란 N개(자기 주문 수) 훔쳐 도주** → 주문 실패 |
| 안 뒤집고 방치 | SMOKE → 스프링클러 → 스테이지 종료 |

- 뒤집힌 뒷면의 익힘은 **면(面)별 doneness 배열 + 파생 함수 재사용**으로 확장한다(M0 스펙에서 검토 완료 — FSM 코드 무수정). 스윗스팟 범위는 **스테이지별로 달라진다**(GDD §6.3) — 수치의 보관 위치(판정 윈도우는 balance.ts라는 GDD §0 규약 vs 스테이지 데이터)는 M1 스펙에서 [DECISION]으로 확정한다.
- 아이템 도난 → 방어 불가 연쇄의 실제 발동(이벤트와의 연결)은 M4다.

## 5. 원형도 채점 — M1 (GDD §6.4)

- 등주부등식 지수: **Q = 4πA / P²** (완벽한 원 = 1.0).
- 구멍(총알): `A_eff = A − ΣA_hole`, `P_eff = P + ΣP_hole` → 자연 감점.
- 반토막(거미): 남은 폴리곤으로 그대로 계산 → 점수 폭락.
- `score = floor(Q_eff × 100 × 1000) / 1000` → **"97.412"** 형식 표기(**floor** 절사 — 반올림 아님). 노이즈 시뮬 특성상 100.000 도달 불가(의도).
- 입력은 블롭의 정점 배열(§2) 그대로 — 별도 지오메트리 변환 없음.
- 스테이지 점수 = **서빙 성공한 계란들의 평균**(소수점 3자리). 주문 실패 손님의 계란은 미집계, 대신 별점 감점(§10).

원형도와 별개로 적용되는 **고정 감점**:

| 감점 사유 | 감점 | 출처 |
|---|:---:|---|
| 노른자 파손 | -15.000 | GDD §6.1 |
| 머리카락 착지 | -10.000 | GDD §8.1 ④ |
| 파리 똥 | -20.000 | GDD §8.1 ⑥ |

이 함수 전체는 **유닛테스트 필수**다(완벽 원·반토막·구멍 1~2개·융합 — [04-testing.md](04-testing.md)).

## 6. 계란 재고 — M1 (GDD §6.5)

- 스테이지 시작 시 `eggStock = 주문 총합 + 여유분(스테이지 데이터)`.
- **깨기 / 로스트(팬 밖 이탈) / 도난(분노 손님·강도)** 모두 재고 차감 — 차감 경로가 여러 시스템에 걸쳐 있으므로 재고는 단일 모델이 소유하고 이벤트로만 갱신한다.
- 매 차감 후 불변식 검사: **남은 재고 < 남은 주문 총량 → 즉시 실패** ("마지막 손님 주문량 때문에 완료 불가" 상황 구현). 실패 연출·화면 전환은 M3.

## 7. 손님 / 주문 — M1 (GDD §7)

- 대기열은 화면에 3~4명 보이게. **맨 앞 손님만 활성 주문**(말풍선에 계란 아이콘 × N).
- v1에서는 **손님 인내심 타이머 없음** — 시간 압박은 익힘 타이머와 이벤트에서 나온다.
- 특수 손님(재채기꾼, 머리카락 트롤)은 일반 손님 스킨으로 줄에 섞여 들어와 **이벤트 트리거**가 된다 — 손님 큐와 이벤트 시스템(§8)의 유일한 접점.
- 서빙 입력은 손님 방향 스와이프가 기본안이나 **DECISION-03 미결** — [DECISIONS.md](DECISIONS.md).

## 8. 방해꾼 이벤트 시스템 — M2+ (GDD §8)

**설계 요구: 새 적 추가가 "JSON 항목 + 핸들러 1개 등록"만으로 가능해야 한다.** 공통 스키마(id / stageUnlock / telegraphMs / responseWindowMs / input 핸들러 키 / cooldownMs / maxConcurrent / onSuccess·onFail 이펙트 목록)는 [02-architecture.md](02-architecture.md) §5.1에 1벌만 둔다(원본 GDD §8).

- 모든 적은 공통 **telegraph → window → resolve** 파이프라인을 탄다: 전조 연출(`telegraphMs`) → 대응 입력 대기(`responseWindowMs`, `input` 키로 핸들러 매칭) → 성공/실패 분기(`onSuccess`/`onFail` 이펙트 키 목록 실행).
- **스케줄러**: 조리 중에만 발생, 스테이지별 `eventBudget` 소진까지 랜덤 간격, 적별 `cooldownMs`(범위)와 `maxConcurrent` 준수. 동시 이벤트는 스테이지 후반부터 허용.

### 8.1 적 요약 (GDD §8.1 — 전부 구현 대상)

| 적 | 대응 입력 | 실패 페널티 | 마일스톤 |
|---|---|---|:---:|
| ① 닌자 거미 | 거미줄 **드래그 절단** | 후라이 **반토막**(폴리곤 절단) | M2 |
| ② 뒷문 강도 | **빠른 더블탭**(고양이 소환) | **노른자 파손**(떠서 도주) | M2 |
| ⑤ 저격수 | 1초 내 **펜싱칼 탭**(패링). 저격수 직접 탭은 **+1 증원 트랩**(최대 3명, DECISION-04) | 후라이에 **구멍**(채점 반영). 팬은 방탄 | M4 |
| ⑥ 파리 | 착지 후 똥 전조(1초) 때 **탭**(비행 중 탭은 안 잡힘) | 해당 계란 **-20.000점** | M4 |
| ③ 재채기 손님 | **팬 뚜껑 탭**(기본안, DECISION-01) | **즉시 게임 오버**(유일한 즉사형) | M4 |
| ④ 머리카락 손님 | **토치 탭** 공중 소각(기본안, DECISION-02) | 해당 계란 **-10.000점** | M4 |
| ⑦ 야간(불 끄기 + 가짜불 스티커) | **스토브 탭** 재점화. 스티커는 열화상에서 파랗게 보여 구분 | 익힘 정지(`heatCoeff = 0`) 지속 | M5 |
| ⑧ 지역 확장(펭귄·악어 등) | — (v1 구현 불필요) | — | **더미 JSON 1개만** — 스키마 수용 증명 |

## 9. 아이템 & 어포던스 미스리드 — M4 (GDD §9)

- 아이템(뚜껑, 펜싱칼, 방패, 토치, 핀셋 등)은 **스테이지 데이터로 위치 정의**(§10의 `items[].pos`).
- **의도적 미스리드가 핵심 재미**: 직관적 정답(방패)이 오답이고 실제 정답은 칼 패링 — 오답 시 개그 연출 + 페널티. "죽어보고 배우는" 디자인.
- 오답 아이템(decoy)도 같은 데이터 체계에 포함: `{"id": "shield_decoy", "correctFor": null, "failGag": "handle_falls_off"}`.
- 미스리드 실패의 페널티는 **점수 손해 수준**으로 제한(즉시 게임 오버는 재채기만). 페널티 강도는 **DECISION-06 미결** — [DECISIONS.md](DECISIONS.md).
- RAW 발사체(§4)로 **아이템을 도난당하면 해당 이벤트 방어 불가 상태** — 이 연쇄도 M4 범위.

## 10. 스테이지 데이터 — M3 (GDD §10)

JSON 스테이지 로더 + 실패 조건 3종(스프링클러/재고 부족/즉사) 처리 + 결과 화면이 M3 범위다. 스키마(background / heatSource / customers / orderRange / panCapacity [DECISION-07 미결] / eggStock / enemyPool / eventBudget / items 배치 / starThresholds)는 [02-architecture.md](02-architecture.md) §5.2에 1벌만 둔다(원본 GDD §10).

- 별점은 스테이지 평균 점수(§5)를 `starThresholds`와 비교해 1~3개.
- 스테이지 1~3은 튜토리얼성(적 1종씩 소개, 열원 가스 고정). 주문 실패가 있어도 스테이지는 계속 — 별점만 감점.
