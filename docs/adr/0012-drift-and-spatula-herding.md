## 맥락 (Context)

기존 원형도는 `시드 노이즈 + 균일 퍼짐`으로 **자동 결정**됐다 — 플레이어는 뒤집기 타이밍과 이벤트
대응만 관여하고, 정작 게임의 목표인 "완벽한 원"을 만드는 **스킬이 없었다**. 뒤집개는 장식이었다.

## 결정 (Decision)

물리엔진 없이(GDD §3 준수) 정점별 반경 오프셋 `flow`로 유사-유동을 구현한다:

1. **드리프트** (`stepDrift`) — 시드 위상에서 천천히 도는 방향으로 흰자가 흘러 그쪽이 불룩해진다
   (cos 폴오프 섹터, 상한 `maxOutPx`). 방치 시 원형도 하락: **Q ~0.99 → ~0.96**.
2. **뒤집개 밀기** (`pushBlob`) — 계란 가장자리 근처 **탭** = 그 지점 흰자를 중심으로 밀어 넣기.
   - **비례 감쇠**: 불룩(+flow)은 자기 크기에 비례해 깎인다 → 크레이터가 안 생기고 탭마다 Q가 단조 회복.
   - **과밀기 페널티**: 이미 0 이하인 정점은 탭당 `dentPerTapPx`(3px)만 패임 — 같은 곳 연타는 손해.
   - 푸시 직후 링 스무딩 2패스 — 눌린 경계 요철 즉시 정리(Q는 요철에 민감).
3. **입력 라우팅** — 짧은 탭: 계란 근처 = 밀기 / 빈 팬 = 깨기. 기존 홀드(뒤집기)·스와이프(서빙)·이벤트 입력과 충돌 없음.
4. **연출/힌트** — 밀 때 뒤집개 날 고스트가 탭 지점에 나타남(`HandsView.poke`) + 스팀 칙.
   불룩 임계(`hintBulgePx`) 초과 시 해당 지점에 초록 탭 물결 힌트(첫 밀기 성공까지).
5. **디버그** — `?debug` HUD에 실시간 Q 표시(250ms 스로틀 — 할당 예산 준수).

## 근거 (Rationale)

- **원형도가 운 → 스킬**: 드리프트 방향이 시간에 따라 돌기 때문에(주기 16초) 한 번 밀고 끝이 아니라
  계속 살펴야 한다 — 익힘 타이밍·이벤트 대응과 겹치는 **주의력 저글링**이 코어 재미가 된다.
- 튜닝 근거(시드 3개 실측): 4초 방치 Q 0.967~0.980 → 밀 때마다 회복 0.983 → 0.986 → 0.989.
- per-frame 할당 0 유지: flow는 Float32Array in-place, 푸시는 탭당 1회.

## 대안 (Alternatives)

- **실물리(matter.js 등) 유체 흉내** — GDD §3 위반 + 성능 예산 초과. 기각.
- **드래그로 쓸어담기** — 거미 drag_cut과 제스처 충돌 + 연타 리듬이 탭보다 둔함. V1은 탭, 드래그 스윕은 M6 후보.
- **밀기 무페널티** — 연타가 정답이 되어 스킬이 사라짐. 과밀기 움푹(dent)으로 견제.

## 결과 (Consequences)

- 점수 분포가 내려간다(방치 시) — 별점 임계·팁 구간은 M6 밸런스 패스에서 재조정 대상.
- 뒤집기 후(flipped)는 드리프트 정지 — 뒤집기 전이 "성형 구간"이라는 리듬이 생김.
- 반토막(frozen) 계란은 밀기 불가(형태 고정 유지).
