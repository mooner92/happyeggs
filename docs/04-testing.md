# 04 테스트 전략

> EGG FLIP (가제)의 테스트 규약 — 무엇을 테스트하고(순수 로직만), 어떻게 결정론을 확보하고, 마일스톤별로 어떤 테스트를 쌓는지 정의한다.
> 테스트 대상 규칙의 SSOT는 [GDD.md](../GDD.md) §0·§6이고, 이 문서는 그것을 실행 가능한 전략으로 풀어 쓴 것이다.

> [!NOTE]
> **현재 상태**
> 코드 0줄, 문서 단계다. 아래의 모든 실행 명령과 테스트 목록은 **예정**이며, M0 테스트의 상세는 [specs/M0-skeleton.md](specs/M0-skeleton.md)(상태: Approved) §8을 따른다.

## 1. 원칙 — 순수 로직만 Vitest

GDD §0 규약: **유닛테스트는 순수 로직에만 작성하고, 렌더링 테스트는 금지**한다. GDD가 명시한 테스트 대상 4영역에 M0 스펙이 3개를 추가했다.

| 대상 | 근거 | 도입 마일스톤 |
|---|---|:---:|
| 원형도 채점 | GDD §0·§6.4 (유닛테스트 필수 명시) | M1 |
| 익힘 모델(FSM) | GDD §0·§13 M0 인수 조건 | M0 |
| 뒤집기 판정 | GDD §0·§6.3 | M1 |
| 이벤트 스케줄러 | GDD §0·§8 | M2 |
| 계란 블롭 모델 | M0 스펙 추가 (M1 채점의 데이터 계약) | M0 |
| 시드 노이즈 | M0 스펙 추가 (블롭 결정론의 전제) | M0 |
| EventBus | M0 스펙 추가 (모델↔뷰 통신의 기반) | M0 |

이 원칙이 성립하는 이유는 아키텍처가 **순수 모델/뷰 분리**를 강제하기 때문이다: `src/systems/`·`src/data/`는 Phaser import 금지(기계 강제 — [05-conventions.md](05-conventions.md) §4). 렌더·입력·연출은 테스트 코드가 아니라 **각 마일스톤 스펙의 인수 조건**(폰 실기 육안 확인)으로 검증한다.

## 2. 결정론 전략

같은 입력이면 언제 어디서 돌려도 같은 결과가 나오게 한다. 세 가지 장치를 쓴다.

| 장치 | 내용 | 효과 |
|---|---|---|
| **dt 주입** | 모델은 벽시계를 절대 읽지 않는다. 시간은 전부 `update(dtSec, …)` 인자로 주입 | 테스트가 시간을 임의로 감아 경계값을 정확히 때릴 수 있음 |
| **시드 RNG/노이즈** | 난수는 전부 시드 기반(`createNoise1D(seed)` 등). 동일 시드 = 동일 출력 | 블롭 형태·캠프파이어 요동 같은 "랜덤"도 재현 가능 |
| **dt 분할 불변성** | `1000ms × 1회 == 10ms × 100회`가 항상 같은 결과여야 한다는 계약을 테스트로 고정 | 프레임레이트(30/60/120fps)와 무관하게 게임플레이 동일 |

> [!TIP]
> **전이 목록 반환**
> 큰 dt 1회로 여러 임계를 한꺼번에 넘어도 중간 전이가 유실되지 않도록, `CookingModel.update()`는 이번 틱의 **전이 목록을 반환**한다. dt 분할 불변성 테스트가 이 계약까지 함께 검증한다.

## 3. 환경·배치

- **Vitest, node 환경.** 순수 모델/뷰 분리 덕에 canvas mock·jsdom이 **불필요**하다 — 테스트 대상이 Phaser를 import하지 않기 때문.
- 테스트 파일은 대상 모듈 옆에 **co-locate**: `src/systems/CookingModel.ts` ↔ `src/systems/CookingModel.test.ts` (`*.test.ts`).
- 렌더링 테스트 금지 규약상, `src/scenes/`·`src/ui/`에는 테스트 파일을 만들지 않는다.

## 4. 마일스톤별 테스트 목록

### 4.1 M0 (specs/M0-skeleton.md §8 요약)

| 모듈 | 필수 케이스 |
|---|---|
| CookingModel | 임계 5곳 경계값 직전/정확(`≥`) · dt 분할 불변성 · GDD 실계수 스케일링(0.8/1.3/2.5 파라미터라이즈드) · `heatCoeff=0` 정지 · 상태 단조성(역행 금지) · 큰 dt 1회에도 전이 목록 무손실 · `smokeCritical` 정확히 1회 · dt≤0 방어 |
| EggBlobModel | 동일 시드 결정성 / 다른 시드 상이 · 정점 수 = VERTEX_COUNT · 평균 반경 단조 증가·상한 준수 · 이웃 스무딩 상한 · 배열 참조 재사용(per-frame 할당 금지 계약) · `getPolygon` 각도 순서 보존 |
| noise | 시드 결정성 · 범위 [-1,1] · 연속성(\|Δ\| 상한) |
| EventBus | on/emit/off · unsubscribe · emit 중 off 안전 · 미등록 이벤트 no-op |

### 4.2 M1

- **원형도 채점** — GDD §6.4가 명시한 필수 케이스: **완벽 원 · 반토막 · 구멍 1~2개 · 융합**. 추가로 `floor` 절사("97.412" 표기)와 스테이지 평균 계산.
- **뒤집기 판정** — M1 범위는 GDD §13이 명시한 **4종(발사/반접힘/이탈/클린)**. 순수 함수 `(익힘 상태, p, 스윗스팟 범위) → 판정`이므로 표를 그대로 파라미터라이즈드 테스트로 옮긴다. 나머지 분기(OVERDONE 분노 도난 연출, 방치→스프링클러)는 해당 기능이 들어오는 마일스톤(M1+·M3) 스펙에서 케이스를 추가한다.
- 계란 재고 불변식(재고 < 남은 주문 → 즉시 실패)도 M1 스펙에서 케이스를 확정한다.

### 4.3 M2

- **이벤트 스케줄러** — `eventBudget` 소진 후 발생 정지 · `cooldownMs` 준수 · `maxConcurrent` 동시 제한 · 조리 중에만 발생. 시드 RNG 주입으로 랜덤 간격도 결정론적으로 검증.

M3 이후의 테스트 범위는 각 마일스톤 스펙 작성 시 정의한다(SDD 루프 ① — [specs/README.md](specs/README.md)).

## 5. 실행 (예정)

| 명령 | 용도 |
|---|---|
| `npx vitest run` | 전체 1회 실행 — 각 커밋·인수 확인 기준 |
| `npx vitest` | watch 모드 — 개발 중 상시 |

- SDD 루프 ④ 검증 단계 = **스펙의 인수 조건 체크리스트 + Vitest 통과**. 예: M0 인수 조건은 "폰 브라우저에서 계란 깨고 타는 것 육안 확인 + 익힘 모델 Vitest 통과"(GDD §13).
- 렌더·입력·연출은 자동화하지 않는다 — **폰 실기 육안 확인**이 공식 절차이며, 확인 항목은 각 스펙의 인수 조건에 체크리스트로 둔다.

> [!WARNING]
> **테스트가 렌더 코드를 import하기 시작하면 설계 위반 신호다**
> node 환경 Vitest가 깨진다면(예: `Phaser is not defined`) 순수 존 경계가 뚫린 것이다. mock을 추가하지 말고 **의존 방향을 고쳐라** — [02-architecture.md](02-architecture.md).
